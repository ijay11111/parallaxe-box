# 05 账号隔离、请求预算与离线证明

阶段 1 · 2026-11-21。安全边界在 core 内，不信任 GUI、agent、配置或目标返回的文本。拒绝发生在产生副作用之前。以下是阶段 2 的设计与验收用例，不是已运行产品的安全保证。

|---|---|---|

### 预算由调度器和传输端口共同执行

1. 只对获准集排队。全局并发 **≤6**、每规范主机 **≤2**；同一主机不同路径共享槽位。队列等待、连接、读体都受同一运行截止时间；每次传输还有单请求绝对截止，不按阶段重置计时。CLI/GUI/agent 只能收紧，不得让重试绕开计数。
2. 每目标一次逻辑 GET、正常只发主请求。首包超过 8000 ms 或 v6 路径确已失败，且能受控选 v4、剩余预算足够，才允许回落一次；取消/结清前次尝试，不争抢并发。有且仅有一个**额外槽**，普通可恢复传输重试与回落二选一。无 HEAD+GET、无 POST、无自动跟跳；限流/授权失败不重试。代理远端族未知不可伪标 v6/v4，不能为回落绕代理。
3. 禁止按头宣告长度无限分配：传输/解码均有有界读取，每响应有效体不超过 **16 MiB**，超过即停止、标记截断，不能以缺字段累计 stale。请求去重键含传输、族、代理模式/路径、接口、方法、完整规范 URL、允许的请求头、内容类型和空体；不同路径/族不合并。同一物理请求只记一次，不因多个证据被重复计数。
4. 分开记逻辑目标、尝试（包括 TLS 前失败）、实际已发 HTTP 请求、独立 DNS/QUIC/出口诊断。`request_count` 指该目标实际送出 HTTP 请求头的次数；未送出为 0；共享一次请求的消费者只引用原尝试，以请求所有者计入总量。运行的 `network_request_count` 为所有独立在线 HTTP 请求的总数，DNS 查询不冒充 HTTP。fixture `Result.request_count` 为样本模拟值，但运行 `network_request_count=0`，另列模拟总数。
5. G5 默认不作 `--interface`/`--proxy` 成对验证；区分请求路径、实际绑定/对端、resolver 路径、回显观察位置及未知项。历史案例的 11 秒不预置到结果。v6 慢但成功、v6 失败而 v4 成功、仅 v6 可用可分别记 `IPv6_SLOW / IPv6_BROKEN / IPV6_ONLY_EGRESS`，不是三个地区。不同路径的国家不能合票。

### 断网 selftest 验收矩阵（设计预期）

断网且禁止真实 socket/DNS，注入固定时钟、内存目录、匿名请求检查器、合成响应和可计数的假系统适配器；不给在线传输、浏览器文件访问或系统写入句柄。测试版可以注入合成的许可以覆盖允许分支，**正式二进制绝不接受 fixture 授权联网**。

| 输入情形 | 期望断言 |
|---|---|
| 浏览器目录、认证环境变量、订阅字段占位；返回 Set-Cookie 后再测另一目标 | 文件/凭据读取次数为 0；非法输入先报错；合法的两次传输描述均只有空 Cookie，无访客状态跨请求，无敏感数据输出 |
| 空许可集，分别使用 simple、full、手动目标、代理、GUI 或 agent | 同选集得到同样的未覆盖原因，真实 DNS/HTTP=0，不能以“离线源不可用”切回在线 |
| 合成 Drive 登录交接、YouTube 挑战、API 403、429 | 不跟跳、不读身份内容、不重试；地区 null；有 HTTP 但不宣称资格 |
| 两个目标共主机、慢 v6→v4、一页截断、运行取消 | 峰值≤6/2，额外尝试最多一次，预算未越界，截断不计 stale；取消后没有新派发，报告区分尝试/实发 |
| 首页内联正例、废弃 `name="region"`、Books 连续合格缺失、204 空体 | 正例只支持相应主张；旧选择器零命中；显式虚拟状态目录时同键三次缺失才 stale，默认永不 stale；204 仅连通。不从 7 天展示窗口推算缺失次数 |
| 计划命中受保护下载域、尝试 apply；三端回放同一组冲突 | 系统写调用数 0，闭包和原因一致，exit 2 与 3 并存取 2；脱敏输出无整份头、IP/标识或正文 |

未来 fixture 细则见 [09](09-signals-and-fixtures.md)，固定归属 `tests/fixtures/<target-id>/<case>/`；元信息含目录键、规则版本、模拟族、内容类型、是否截断与合成的响应片段。只保留白名单键与合成值，打 `fixture=true`；生产 CLI 不提供自动录制真实会话的命令。最后比较运行前后默认路由、代理、hosts、防火墙快照摘要与假系统调用计数；离线测试证明程序契约，不能替代真实跨平台路径验证。

### 唯一可选的历史状态：`--state-dir`（ADR-004）

默认模式不发现、不打开、不创建目录，不从 GUI/agent、配置或环境变量隐式开启；即使进程常驻，单次缺失也只给 `UNKNOWN + FIELD_MISSING`。只有由用户在进程启动时显式传入本地 `--state-dir DIR`，才开放专用于规则新鲜度的最小读写能力（不等于允许写网络规则）。agent 单条请求不能追加目录。

未来文件 `freshness-v1.json`：`{schema:"parallaxe.freshness/v1",entries:[{key_digest,rule_version,last_hit_at,last_comparable_at,misses,last_run_digest,quarantined}]}`。日期为 UTC；`misses` 饱和在 3。键按长度分隔的目标 ID、规范 URL（含固定查询）、表面、规则 ID/版本、请求形态、实际族与稳定路径标识生成不可逆摘要；不存原 URL 查询、代理地址、接口名、回显 IP 或内容。没有可比路径/历史命中就不建计数。不按同一内容反复重放累加。一条已隔离的记录不是自动放行授权。

只在用户指定目录内用专用锁、临时文件和原子替换，拒绝符号链接/重解析点、网络共享或冲突写入。读取/更新时自动丢弃距最后合格命中超过 7 天的计数；时钟倒退不复用旧记录。目录不可写、文件损坏、未知 schema、锁异常时给出脱敏状态错误，不能退到默认家目录或凭空报 stale。合成 selftest 可以显式注入虚拟 state-dir 分别测试开/关、跨进程同键、换版本、并发去重及第 8 天失效；不会触碰用户真实状态。
