# 06 本机阻断：先判断是否应该给出规则

研究日期：2026-11-21。本报告比较方案，没有生成规则、测试内核、写配置或改变网络。当前 03/04 的样本都不能准入。**默认动作是不阻断；通过所有门槛且用户要求方案时，首选精确域名的代理层预览。** 规则生成、导出文件、用户导入、实际生效是四件事。

| 顺序与方案 | 适用前提及收益 | 局限、误伤与退路 |
|---|---|---|
| 0 只提示（永远可用） | 无管理员权限、证据弱、目标共享或用户未选择时，列出异常与保护原因；不改变本机 | 不拦流量，不能称“已隔离”；可展示受影响服务而不给可应用片段 |
| 1 代理层 REJECT，首选的阻断预览 | 用户已有兼容的 Mihomo/Clash 规则模式或支持相应动作的 sing-box；精确主机、路径确实经过该内核、规则优先序正确，才可能生效 | 严格 Global 绕过该类域名分流；旁路进程/直连不受控，同主机不同 HTTPS 路径不能分开。P0 只显示；以后也不改用户配置、不自动导入/热重载 |
| 2 hosts 受管区块，延后 | 仅对使用本机名称解析的程序；精确域且能限定本工具区块时才可评估；便于逐项审阅 | 影响整机，多地址族、缓存、自带 DoH/远端解析可使计划无效。不接管整个文件；权限、冲突或不支持安全替换即不写 |
| 3 本机出站防火墙，最后评估 | 仅限受管设备、有权限且平台能表达足够窄的条件；独立可识别的规则可单独撤销 | 规则语义随平台而异；共享 IP、Anycast 和动态地址不能代表服务。**禁止按 IP、CDN IP 或 ASN 阻断**。不能精确限制就不提供此方案 |
| 补充：本地 DNS sinkhole（规格 §3.7） | 仅对显式使用该受管 resolver 的应用有效 | 同 hosts 一样分不清同主机路径；远端 DNS/加密 DNS/缓存可旁路；不部署服务、不改 DNS，阶段 0 只作比较 |

模式与动作依据：[Mihomo 运行模式](https://wiki.metacubex.one/en/config/general/)、[匹配顺序](https://wiki.metacubex.one/en/config/rules/)、[sing-box 官方规则动作](https://sing-box.sagernet.org/configuration/route/rule_action/)。语法有版本差异，文档可查不等于用户内核已支持；不要用“检测到代理”代替生效证明。

## 保护清单和影响闭包

完整种子采用 TECH-REF §D（内部技术参考，不随仓库公开）（只增加保护，不以社区清单证明域名独占），并合入原规格 §17.2。包括 `gstatic.com`、`googleapis.com`、`googleusercontent.com`、`ggpht.com`、`gvt1/2/3.com`（三个域）、`dl.google.com`、`dl-ssl.google.com`、`xn--ngstr-lra8j.com` 及下载子域；还包括身份/OAuth、付款、验证码、字体/存储、证书验证、Android 激活/推送/更新链、`www.google.com` 与 Play 共享前端。[Google 管理的 Android 网络要求](https://support.google.com/work/android/answer/10513641?hl=en)将 gvt1 等列为下载，将 gvt2/gvt3 列为连接监控/诊断，并列 `crl.pki.goog`、`ocsp.pki.goog` 为证书校验。保护均保留，但不把所有 gvt 域写成实际下载端；TECH-REF 的 `cri.pki.goog` 拼写无官方佐证，另见 ADR-002。S2 的 CDN 路由只是个案。商店可见与安装包可下载分别观测，不能靠封一个共享后端来区分服务。

1. 先记用户选择、保护优先级、所选路径及证据；仅对 `RESTRICTED/BLOCKED`、直接且高可信、有明确归因、`guard_eligible=true` 的目标考虑下一步。403 单值、`UNKNOWN/CONFLICT/REACHABLE_ONLY/SIGNAL_STALE`、未测、条款不许测试均不准入。
2. 以候选精确主机集合 B 起步；主机大小写、尾点、国际化域名统一，按完整 DNS 标签匹配根/受保护子域和明确枚举的别名，不用裸字符串前缀。把“服务依赖主机/服务”的关系画成有向边；重定向、共享主机、别名和登录/支付/下载交接分开标来源、时效和未知。没有边不等于无依赖。
3. `impact_closure = B ∪ shared_domains ∪ reverse_dependencies ∪ protected_login_chain`：只并入从 B 相关的节点；遇同主机其它表面/共享后端，找出**反向**依赖它的所有服务，再沿它们的关键依赖/受影响上游迭代至无新增，去重防环。保存每个节点的首条理由链，而不是把全世界的保护种子无条件并入每个 B。
4. 命中 SHARED/UNKNOWN、关键服务或用户保护项、登录/付款/下载依赖，或独占性/路径未证，`safe_to_apply=false`，不给可直接应用的规则；理由分别为 `GUARD_DEFERRED_SHARED_CDN`、`BLOCK_DEFERRED_DEPENDENCY_CONFLICT` 或 `NO_SAFE_BLOCK`。仅专用域、完整已知的低风险闭包才可**提议**精确域预览，仍不自动应用。不按进程名推断同一浏览器中的业务，不做 TLS 解密。

**纸面走查**：选停 Play 某下载表面 → B 含 `dl.google.com` → 命中共享分发 → 同时影响 Play/更新 → 即使下载表面被用户设为 OPTIONAL 仍否决；报告显示两条依赖及回退到只提示。选停 Flights → 主机 `www.google.com` 与 Search 共用 → 不能按 HTTPS 路径区分，否决。独立的用户既有路径只有在确有证据时才能另报 `ROUTE_ISOLATED`；共享出口保证仍未证。以上不是实机阻断测试。

## 写操作的生命周期（后续门控要求，非本轮实施）

- P0 `guard plan --dry-run` 只输出内存预览，不落盘。展示选择人 `USER`、计划标识、操作、受影响服务/域/共享路径、证据、限制、预计副作用与回滚方式；用户未明确选定、Global 模式或内核未确认，仅提示。
- 未来 `--apply` 才允许与已展示计划一致的独立文件/受管区块操作；导出代理文件不等于安装。写前重新校验目标、闭包、权限及原文件摘要；同一计划已存在即无变化。备份原件/权限，以锁和同目录临时文件校验、原子替换；防火墙只能用平台支持的事务或逐条可逆、带所有权标记的操作，不能承诺文件替换对防火墙有效。
- 任一步失败停止，恢复已完成的本工具动作并复核，还原失败须报部分失败及人工恢复方法。`guard revert` 只撤本工具的区块/规则/导出文件；若用户在此后修改过，先比对，拒绝用旧备份覆盖新改动。重复撤销无额外影响，代理文件撤销不保证用户另行导入的外部配置已撤销。
- 本机审计仅记时间、计划 ID、用户选择、前后摘要、范围、结果及回滚状态；不写账号、完整地址、原始头或用户整份配置。能做的是停止本机流量，不是改变远端共享 IP 画像。对外固定：`LOCAL_TRAFFIC_ONLY`；`remote_account_impact=NOT_PROVABLE`；`shared_egress_guarantee=UNPROVEN`。
