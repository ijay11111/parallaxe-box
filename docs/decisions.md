# 工程决策摘要（公开版）

> 本文汇总影响产品行为的关键工程决策，供使用者与安全审阅者理解"为什么这样设计"。
> 内部裁决过程、讨论记录与原始提示词不随公开仓库发布。

## 1. 数据与判定契约
- **报告 schema 稳定**：`parallaxe.report/v1` 的必需字段与枚举不随界面语言、平台或版本漂移；CLI `--json` / agent 协议输出保持机器可读且跨语言字节一致。
- **9 个明确状态**：`OK / RESTRICTED / BLOCKED / REACHABLE_ONLY / LOCAL_PATH_ERROR / CONFLICT / UNKNOWN / SIGNAL_STALE / UNSUPPORTED`。证据不足用 `UNKNOWN`，同层矛盾用 `CONFLICT`，过期信号用 `SIGNAL_STALE`，不压缩成单一"正常/异常"。
- **退出码**：0=无明确异常，1=配置/输入错误，2=存在明确异常，3=不确定/证据不足；2 优先于 3。
- **来源分层**：区分官方文档、直接匿名观测、社区报告、遗留代码、推断；推断不冒充观测。

## 2. 目录与来源可信度
- 域名对照表计数只看**可复核来源**；404 源不算第二个独立来源；社区表只作交叉核对，不证明域名独占或可封禁。
- 政策/用途以官方为准；某条具体响应以带上下文的直接观测为准；历史字段与新版资料冲突时按所回答的问题分别取舍。

## 3. 匿名与隔离边界
- 默认零发包：计划生成、报告导出、目标导入均不产生网络请求；实际检查需显式运行并受一次性许可约束。
- 不读取浏览器 Cookie、账号、订阅、凭据；不宣称能证明账号国家或购买资格。
- 默认零写盘：状态目录仅在显式指定时启用；规则预览 `applied=false`、`rules_written=0`。

## 4. 阻断与规则导出
- **规则导出是核心能力**：用户把本软件生成的 Clash/sing-box 规则或域名清单导入到自己已有的代理/过滤工具；软件不接管用户节点与分流。
- **测试版不含系统级阻断**。Windows 和 Linux 的防火墙写入与撤销均关闭。`guard status` 可以只读查看既有审计。
- **共享基础设施绝对保护**：登录、付款、Play 下载、共享 CDN（如 gstatic/googleusercontent/googleapis/gvt1/clients2-6）永不自动阻断；无法安全阻断时明确输出 `NO_SAFE_BLOCK`。
- 用户导入规则后，实际效果取决于用户所用工具、运行模式及既有分流配置。
- **手动导出**：CLI 须指定 `--out-dir <目录>`。若闭包完整且唯一警示是 `NO_SAFE_BLOCK`，可带 `EXPORT_WARNING_NO_SAFE_BLOCK` 导出静态文件，由用户自行审阅和导入，`applied=false`。其他未解除的否决原因仍阻止导出。
- **整包替换**（用户自主选择）：可生成完整规则覆盖原分流，但必须强警示先备份；软件不替用户执行替换。

## 5. 探测安全
- 批量探测前评估流量与会话风险；节点/协议分层调度，UDP/QUIC 采用保守间隔与小批次，发现本地 QoS 迹象自动暂停同协议探测。
- 区分地区信号与服务可达性：地区信号正常但请求超时要分别记录，不合并成单一结论。
- 不使用"页面默认语言""域名尾缀""解析 IP 地理库"推断出口地区——这些反映语言偏好、客户端版本或解析器位置，不是出口地区。

## 6. 网络可达性与订阅资格的分界
- 本软件是**匿名网络层检测工具**：只回答"当前出口在各服务眼里观察到什么、链路质量如何"，**不验证也不推断**账号国家、订阅资格、年龄、付款档案、家庭组或组织策略。
- 报告中的资格提示是**能力边界说明**（静态、默认不参与判定）：提醒"网络可达 ≠ 订阅可用"，并给出官方帮助链接由用户自行核对；它不是一项检测结果，也不进服务矩阵的判定列。
- 账号隔离与不读凭据的约束见 [docs/account-isolation.md](account-isolation.md)（安全边界证明）。
